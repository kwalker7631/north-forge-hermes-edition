## Validation order

Use a disposable/test USB or clone. Do not sacrifice a working field drive.

1. Put `north-forge-agent` at engine commit `83c85b3f037b6f235dcbbb412ab167547cb67b5f`.
2. Put the Kyocera/private pack at this recovery branch.
3. Preserve `north-forge-agent-data`; do not copy a venv from another host.
4. Launch through `Start North Forge` / `north-forge.cmd`, not a bare `hermes` command.
5. Allow one bootstrap/venv repair when moving to another computer or drive letter.
6. Verify the launcher log reaches `result=ready`.
7. Verify `HERMES_HOME` points at the drive-local data directory.
8. Use `Check-HermesPath.ps1` to confirm host PATH confusion is not affecting diagnostics.
9. Configure inference with the drive-local executable / `Set-Inference.ps1` if needed.
10. Ask one real test question before testing dashboard or optional components.
11. Move/re-letter the same logical drive and repeat launch to verify portability and data preservation.

## Rule for restoring later work

Do not merge the post-`bf64e7f` block wholesale.

For each later idea:

- identify the exact commit and files,
- state the user-visible requirement it solves,
- confirm it does not redefine the physical layout or launcher contract,
- test it on the recovery baseline,
- keep it only if the test proves a real improvement.

Runtime evidence wins over documentation claims.

## Main branch safety
