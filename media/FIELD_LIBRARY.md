# The shelf on the stick

A tech already works this way: manuals in a binder, photos on the phone,
logs from the last call, a wiring diagram folded in the door. The stick
is that binder.

## Drop, don't organize for the model

Web dashboard Files page and the Terminal both take drag-and-drop.
Hermes records where the file landed. Put things where a person would:

| Goes in | What |
|---|---|
| `Docs\` | Service docs, parts books, wiring, procedures you are allowed to keep |
| `IMG\` | Panel shots, error screens, cracked frames, the 3D-printed gear |
| `audio\` | Short clips if that is how the symptom sounds |
| paste / drag into chat | This ticket's log or screenshot — evidence for *now* |

Customer names and ticket numbers stay on this volume. They do not sync.

## How the desk uses it

Hotline code, nothing useful on the public web → search `Docs\` first.
If the PDF is in the folder, quote the page you can see. If the PDF is
scanned and has no text layer, say so and ask for the page photo.

No manual and no public page → honest gap. Do not invent a code meaning.

## Field reality

There is no problem that cannot be worked. Techs have welded cracked
frames and printed plastic gears when the list price was a joke. That is
**field reasoning**, labeled as such — not a factory procedure. Offer it
when parts are NLA or absurd. The tech still decides. Manufacturer docs
in `Docs\` still win when they exist.

Knights may push a *sanitized* diagram or note to community. The binder
on the stick stays the binder.
