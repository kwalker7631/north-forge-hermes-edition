# The shelf on the stick

A tech already works this way: manuals in a binder, photos on the phone,
logs from the last call, a wiring diagram folded in the door. The stick
is that binder.

## Fastest way to feed the desk

1. **Copy and paste text.** Code, model, SN snippet, Event Viewer line,
   driver version. Fastest. Searchable. No pixels to guess.
2. If it will not copy — panel, grayed menu, paper label — **screenshot
   and paste into this chat.** Snagit (or Win+Shift+S): select the area,
   highlight if you need to, drop from the clipboard into the session.
   Do not save-to-disk-then-browse unless the file must live in `IMG\`.

The session is the job folder for *this* call. `Docs\` / `IMG\` are the
binder for next month.

## Drop, don't organize for the model

Web Files and Terminal both take drag-and-drop. Hermes records the path.

| Goes in | What |
|---|---|
| Paste into chat | This ticket: text first, then a Snagit crop |
| `Docs\` | Service docs, parts books, wiring you may keep |
| `IMG\` | Shots you want again (not the one-off paste) |
| `audio\` | Short clips if the symptom is a sound |

Customer names and ticket numbers stay on this volume. They do not sync.

## How the desk uses it

Hotline code, nothing useful on the public web → search `Docs\` first.
If the PDF is there, quote the page you can see. Scanned, no text layer:
say so and ask for a photo of the page.

No manual and no public page → honest gap. Do not invent a code meaning.

## Field reality

There is no problem that cannot be worked. Welded frames and printed
gears are **field reasoning**, labeled as such. Factory paper in `Docs\`
still wins when it exists. The tech still decides.
